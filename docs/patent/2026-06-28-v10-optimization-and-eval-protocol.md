# myAgent v10 优化说明与盲测协议

日期：2026-06-28  
项目：`D:\AAAcode\code-code\agent+\myAgent-main`

模型口径：DeepSeek API，`deepseek-v4flash` 映射为 `deepseek-v4-flash`

## 1. 本轮目标

本轮优化目标从“继续极限省 token”调整为“高风险题增强协作/二次校验”。判断标准如下：

1. 准确率优先，myAgent 需要超过或至少稳定比肩 MACT。
2. token 不再追求极低，只要平均 token 不超过 MACT 的 70% 即可接受。
3. 每轮代码修改后，先做每数据集 50 条盲测；只有 50 条盲测已经成功，才进入每数据集 200 条确认。
4. 200 条结果只作为最终确认，不作为每次调参的默认步骤，避免不必要 API 消耗。

## 2. 本轮发现的主要问题

### 2.1 强复核候选没有真正进入最终仲裁

现象：强复核阶段已经生成了 `thinking_direct`、`thinking_audit`、`thinking_program` 等候选，但 `agreement_decision` 仍停留在强复核之前的旧候选集合。结果是有些正确复核答案没有覆盖旧答案。

处理：在强复核候选生成后，重新构建包含全部候选的仲裁结果，并把最终选中的候选写回 `agreement_decision`。

专利可写点：高风险题不是简单调用一个额外 LLM，而是把代码候选、审计候选、程序化候选统一进入候选答案一致性判定。

### 2.2 确定性语义算子被语言复核覆盖

现象：WTQ 的 “top placing competitor” 已经由确定性 rank 算子算出正确答案，但后续语言复核有时会把它覆盖成错误答案。

处理：新增 `deterministic_shortcut_applied` 与 `deterministic_shortcut_reason`，并提高确定性候选置信度。非强制 fallback 情况下，语言复核不能轻易覆盖确定性算子答案。

专利可写点：确定性语义算子的结果作为高可信候选参与仲裁，并具有保护权重。

### 2.3 WTQ 数字答案被错误补全为文本实体

现象：WTQ 中答案 `2` 被标量规范化误补成表格单元格文本 `B1-2 details`。

处理：`_canonicalize_wtq_scalar` 对纯数字答案直接保留，不再做实体单元格扩展；只有文本实体才进入完整单元格补全。

专利可写点：答案规范化要区分数值 denotation 和实体 denotation，避免把数字片段误当作实体片段。

### 2.4 CRT 组合答案顺序与评估口径不一致

现象：CRT 组合题中，模型输出 `ted humphrey & dean parisot`，gold 口径是 `dean parisot, ted humphrey`。逻辑上找到了正确二元组，但输出顺序不匹配。

处理：`_canonicalize_crt_scalar` 在组合题中根据表格列顺序重排答案片段。例如表头是 `directed by`、`written by`，则输出按表头顺序规范为 `dean parisot, ted humphrey`。

专利可写点：答案规范化不仅做字符串清洗，还可根据表格 schema 对组合答案进行结构顺序校准。

### 2.5 TabFact 拼写噪声导致事实匹配失败

现象：题干中出现 `qilliam ivey long`，表格中为 `william ivey long`。这是轻微拼写噪声，语言复核和代码候选都可能误判为 false。

处理：新增 TabFact 原子事实模糊行匹配算子。该算子只在非比较、非否定、非聚合的简单事实句中触发，允许长度足够的实体 token 存在一处编辑差异。

专利可写点：面向表格事实验证的轻量噪声容忍匹配，不依赖 gold answer，不绑定具体样本 ID。

### 2.6 CRT 连续年份和类别优势题缺少程序化校验

现象：CRT 中 “是否有运动员连续年份获奖” 以及 “是否存在更容易被认可的奖项类别” 属于存在性/趋势性闭集问题，纯 LLM 复核不稳定。

处理：

- 新增 `_crt_consecutive_year_medalist_answer`，从 year 列和 gold/silver/bronze 等奖牌列提取实体，判断同一实体是否出现在相邻年份。
- 新增 `_crt_recognition_category_advantage_answer`，对 award/category 列做主题 token 统计，识别某一类别主题是否重复出现。

专利可写点：对闭集 yes/no 高风险题引入可插拔程序化校验器，减少纯语言判断漂移。

### 2.7 Windows 输出文件锁导致长实验中断

现象：运行 200 条时，如果同时读取 JSONL 文件统计行数，Windows 可能短暂锁住文件，导致 Python 追加写入 `PermissionError`。

处理：`tqa.py` 新增 `_append_jsonl_with_retry`，写输出时遇到 `PermissionError` 会短暂重试，避免实验直接中断。

专利可写点：该项属于实验工程稳定性，不建议作为专利核心。

## 5. 后续固定评测协议

后续每轮优化按以下规则执行：

1. 代码改动后先跑单元测试。
2. 每个数据集只跑 50 条盲测。
3. 若 50 条结果满足以下条件，才进入 200 条确认：
   - 总体准确率高于 MACT；
   - 至少两个数据集不低于 MACT；
   - 平均 token 不超过 MACT 的 70%；
   - 没有明显单数据集灾难性回退。
4. 200 条运行期间不读取输出 JSONL 文件，只看进程结束后的结果。
5. 200 条结果若失败或被中断，不写入正式结论，只记录为中途实验。

## 6. 可写入专利的最终技术点

建议写入专利报告的核心技术点：

1. 风险驱动的选择性协作机制：根据题型、证据缺口、候选分歧和执行失败决定是否增加推理成本。
2. 答案契约机制：在推理前确定 scalar/list/tuple/label、闭集标签、小数精度和输出形态。
3. 证据包机制：统一候选行、候选列、实体匹配、缺失项、操作信号，供多个推理组件共享。
4. 候选答案一致性仲裁：把代码候选、语言复核候选、程序化复核候选放入统一仲裁。
5. 确定性语义算子保护：可程序化验证的问题优先使用通用算子，并在仲裁中给予高可信权重。
6. 数据集 profile 适配：允许 WTQ、TabFact、CRT 在同一框架下使用不同答案契约和缺失值策略，但不使用样本 ID 或 gold answer 决策。
7. 高风险闭集题二次校验：对 yes/no、true/false、more/less/equal 等题型增强程序化复核。

不建议作为专利核心的内容：

1. DeepSeek API 接入。
2. 命令行参数和模型切换实现。
3. 具体某个样本的修复。
4. Windows 文件锁写入重试。
